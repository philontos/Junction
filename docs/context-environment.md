# Context 环境清单设计

状态：采集原则已确认（2026-11-18）；字段细节仍为设计草案，尚未实现环境采集与差异检查。现有能力见 [本机联调文档](junction-local.md#工作区边界)。

目标：让接手的人和 Agent 知道原任务使用了什么环境、哪些条件是必需的，以及当前设备缺少什么。共享仍是一键完成，未采集到的信息不阻断保存。

## 已确认的采集策略

**按统一规范先采集，后续按需读取；采集范围限定当前任务。**

1. **分享时采集基础快照**：系统、仓库与 commit、当前 Agent、常用运行时版本、项目依赖文件引用，自动完成，无需用户填写清单。
2. **同时保存任务相关证据**：从任务记录和明确的项目配置中整理涉及的工具、skills、服务、外部文件和权限需求。只采集相关条目；版本、位置或可用性未知时明确标记，不推测补全。
3. **未采集项保留状态**：类别框架完整，未实现、未探测或探测失败的项可为空并附原因，不为填满清单扫描整台设备。私钥和令牌不进入清单。
4. **接续时按需读取和检查**：先读环境概要，再按下一步任务补读相关条目、核对当前设备；不要求 Agent 每次完整阅读和检查所有环境项。
5. **补查与原快照分开**：接收方新查到的是接收设备当前状态，写入独立检查结果。来源设备后续补采需要形成新版本，并记录实际观察时间；不能倒填成旧版本发布时已知的事实。
6. **保留分享时的证据**：来源设备离线或环境变化后，已保存的清单仍可离线读取。同一次分享的重试复用已固定的采集结果；采集有缺口时仍可完成归档。

## 清单范围

| 类别 | 记录内容 |
| --- | --- |
| 来源与系统 | 来源设备、采集时间、操作系统、架构、shell |
| 工作区 | 仓库、分支、commit、工作目录、未提交状态；继续引用现有工作区元数据 |
| 运行时与依赖 | Node/Python 等版本，项目依赖与锁文件的相对路径、校验值，项目声明的版本要求 |
| Agent 与工具 | Agent、CLI、MCP 的名称、版本、任务相关配置引用 |
| Skills | 名称、来源、版本或内容校验值、来源位置 |
| 环境变量 | 名称、用途、是否必需；值默认不采集 |
| 服务与连接 | 任务使用的服务、端口、SSH 主机别名、网络要求 |
| 文件与数据 | 任务依赖的附件、数据集、外部目录；是否已包含或仍依赖来源设备 |
| 权限与认证 | 所需能力，如仓库读取、SSH 登录；凭证逻辑引用及当时已知的认证状态 |

按任务范围采集。安装在 A 上的工具不自动成为任务依赖；日志里没出现的工具也不能直接断定未使用。依赖文件优先记录引用与校验值，不复制完整包列表。观察到的版本不自动成为接收方必须使用的版本。

## 存储与兼容

- 使用可选 JSON 扩展，拟定为 `extensions["junction.environment/1"]`，随固定 Context revision 保存。自然语言只补充用途和说明。
- 清单与 Claude、Codex 等 Agent 无关；采集器可以逐步增加。扩展有自己的版本和采集器版本。
- 原有 `switchyard.workspace/1` 或 `switchyard.capture/1` 继续作为本接入器的工作区信息来源；清单不再复制一份仓库和 commit。其他接入器可提供各自的工作区信息。
- 来源设备 ID 是引用，不包含连接权限。来源绝对路径仅供定位，接收方需要映射成本机路径。
- 旧 Context 没有环境扩展时仍可读取与接续，环境显示为“未记录”。未知类别保留，不能因不认识而推断满足要求。
- 清单表示采集时的事实。来源机器之后的变化不改写旧 revision，也不代表能够恢复进程、内存或文件系统现场。

## 空值和状态

每组都有采集覆盖状态 `coverage`：

| 值 | 含义 |
| --- | --- |
| `not_collected` | 尚未采集；省略该组也按此处理 |
| `partial` | 只取得部分信息，附缺口原因 |
| `collected` | 本次声明的任务范围内已采集完成，不代表扫描了整台设备 |
| `not_applicable` | 有依据确认这类环境不适用于任务 |

组内条目分别记录：

- **观察结果**：`observed.status = present / missing / unknown`，以及结构化值、来源和观察时间；可继承清单的采集时间。
- **任务要求**：`requirement.level = required / optional / unknown`，以及已知约束和依据。默认 `unknown`。
- **出处**：本机探测、项目配置、日志记录或人工说明。日志里的旧事实使用日志时间，不能冒充发布时的实时检查。

`null` 表示未知，不表示没有。空数组需要结合覆盖状态解释。未使用、未采集、探测失败、已确认缺失不能混为一种状态；失败或不适用时附原因。是否必需只接受有依据的声明，不根据“机器上装了它”推断。

精简结构示例（示意数据，不是已经采集的生产记录）：

```json
{
  "schema_version": "junction.environment/1",
  "captured_at": "2026-11-18T06:00:00Z",
  "collector": { "name": "switchyard", "version": "example" },
  "groups": {
    "runtimes": {
      "coverage": "partial",
      "note": "只检查了任务使用的 Node，其他运行时未检查",
      "items": [
        {
          "id": "node",
          "observed": {
            "status": "present",
            "value": { "version": "24.15.0" },
            "source": { "kind": "local_probe" }
          },
          "requirement": { "level": "unknown", "constraint": null }
        }
      ]
    },
    "skills": { "coverage": "not_collected", "items": [] },
    "access": { "coverage": "not_collected", "items": [] }
  }
}
```

## 接收方检查

1. 下载固定版本，先读取环境概要和采集缺口，再按当前任务需要读取具体条目；先检查当前仓库和相关运行环境。
2. 将工具、路径、服务与凭证引用映射到接收设备，生成独立的本地检查结果，关联来源 Context/revision、检查设备与时间。
3. 结果逐项标记“已满足 / 有差异 / 缺少 / 未检查 / 不适用”。有明确要求且通过检查才能标为已满足；版本不同但兼容性未知时只标有差异。
4. Agent 优先处理与下一步工作相关的差异。无关项不阻塞接续；需要登录或授权时再提示用户。源设备曾认证成功不代表当前设备已经获得权限。

检查结果不覆盖来源清单。安装依赖、连接远端、运行历史命令均遵循当前环境的权限，读取清单本身不触发这些操作。

## 实现边界

- Switchyard 负责在执行设备采集、检查和匹配环境；Junction 校验、保存并转发这份描述，不探测用户设备。
- 首轮采集优先覆盖系统、已有 Git 信息、当前 Agent、常用运行时，以及项目依赖文件引用；已有日志或项目配置能明确提供的任务相关信息也按统一清单记录。其他类别保留入口，未实现的采集器明确标记未采集。
- 自动采集采用明确字段和只读探测，设置时限和容量上限；失败保留原因，不阻塞 Context 归档。纯 JSONL 导入只能记录日志证据，不能伪造实时环境快照。
- 不读取或上传 SSH 私钥、令牌、完整 `.env`、SSH 配置或进程环境变量；允许分享的非敏感固定配置使用显式白名单。凭证逻辑引用由执行设备自行解析，不能充当授权。
- 清单中的命令、URL、文件路径均为历史资料；不直接作为采集或检查指令执行。原始 JSONL 的敏感内容处理是另一项边界，环境清单不保证原始日志已经脱敏。
- UI 默认仍保持简洁：共享流程自动采集；接续时主要展示相关缺口，完整清单收在详情中。

实施验收应覆盖：空清单和旧版本可接续、采集超时不中断归档、缺失与未知不混淆、可选项缺失不误阻塞、路径可重映射、认证不继承，以及日志证据不被当成实时状态。
